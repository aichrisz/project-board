# Project Board v0.8.1 — Reliability Plan

**Status:** Approved by Abel on 2026-07-29\
**Implementer:** OpenCode · `abel-claude/kr/claude-opus-5`\
**Scope:** Reliability/security patch; no feature expansion, no push/deploy.

## Goal

Ship a local-first reliability patch that rejects malformed or oversized import data safely, establishes regression tests for the touched boundary, resolves the audited runtime router advisory only with a verified compatible version, and makes the existing GitHub Pages workflow/documentation trackable and current.

## Non-negotiable constraints

- Keep Project Board local-first, single-user, English, and dependency-light.
- Do not add cloud/auth/telemetry/backend functionality.
- Do not disable TLS/audit checks or use `npm audit fix --force`.
- Do not push, deploy, modify GitHub settings, expose secrets, reset/clean unrelated work, or delete existing user data.
- Preserve the existing untracked `.github/workflows/pages.yml`; review and track it as an intentional source file.
- Follow RED → GREEN → REFACTOR for production logic. Record actual test commands/results in the final change summary.

## Task 1 — Test foundation and strict import boundary

### Acceptance criteria
- Add a minimal, maintained test command that can exercise TypeScript import parsing.
- Write tests before production changes and observe expected failure.
- Import rejects invalid root data, malformed project/step shapes, unsafe status/type values, invalid dates/settings, duplicate or blank identifiers, and files above a documented safe byte cap.
- Valid v1 exports still parse; additive legacy fields continue to migrate safely.
- Error messages are user-safe and actionable, without stack traces or source internals.

### Verification
- Targeted import tests pass.
- Full test suite passes.
- `npm run build` passes.

## Task 2 — Dependency remediation

### Acceptance criteria
- Investigate the exact React Router advisory and update only to a non-vulnerable, compatible version.
- Do not use forced audit remediation or unreviewed major migration.
- Lockfile is generated by npm and reviewed.
- `npm audit --omit=dev --audit-level=high` has no unmitigated reachable high/critical finding, or a documented, evidence-backed exception if no safe upstream fix exists.

### Verification
- Dependency tree and native audit result are recorded.
- Tests, lint, TypeScript build, and Pages build pass after the change.

## Task 3 — Delivery hygiene

### Acceptance criteria
- Track `.github/workflows/pages.yml` after confirming it uses least-privilege Pages permissions and the correct `/project-board/` base.
- Update README, portable feature spec, and project plan references from stale v0.7/Grok routing to v0.8.1/OpenCode Opus 5 where applicable.
- Bump visible/package version consistently to `0.8.1` and add a concise human-readable changelog entry.
- Do not commit build output, `node_modules`, credentials, or local preview artifacts.

### Verification
- `npm run lint`, tests, `npm run build`, and `npm run build:pages` pass.
- Pages-base preview serves `/`, `/review`, `/project-board/`, and `/project-board/review` with expected HTTP responses.
- Git diff is scoped; secret scan of staged changes is clean.

## Checkpoints

1. **After Task 1:** import tests are red then green; baseline build remains healthy.
2. **After Task 2:** router update is evidence-backed and audit result is reviewed.
3. **After Task 3:** full quality gate and local Pages smoke test pass; no remote push.

## Out of scope

- New dashboard, kanban, review, sync, multi-user, cloud, i18n, or design features.
- Production deployment or GitHub Pages configuration changes.
- Unrelated refactors, broad dependency upgrades, and deletion of stale code outside this reliability scope.
